# LinkaVel コードレビュー & バランス診断（2026-08）

対象コミット: `7423006` 時点のコード一式。
目的: (1) バグ・UI不具合の洗い出し / (2) 5デッキのバランス評価 / (3) ルール改正の方向性提案。

# 1. 不具合一覧

重大度: **A = ゲームが壊れる / 不公平**、**B = 挙動がルールと食い違う**、**C = 見た目・軽微**

## 1-A. ゲームロジック（重大度A）

### A-1. 同名カードの取り違え（`main.js:609`, `main.js:932`, `cpu_logic.js:139`）
```js
const handIndex = p.hand.findIndex(c => c.id === cardData.id);
```
カードは `getCardData()` でディープコピーされた**別インスタンス**なのに、`id` 文字列で手札を検索している。
同名カードを3枚積む前提のゲームなので、「場に出したインスタンス」と「手札から消したインスタンス」が食い違う。
`_tempBuffs` / `_usedLimits` / `_hasAttacked` などの個体状態が別カードに付いてしまう。
→ **`p.hand.indexOf(cardData)` に統一する。**

### A-2. 決着後もゲームが進行し続ける（`main.js:1039-1083`）
`damagePlayer()` は LP が 0 になると `endGameSequence()` を呼ぶだけで、**ゲーム終了フラグがない**。
- リザルト表示中も CPU のターンが裏で進み、追加で `endGameSequence()` が呼ばれると
  `result-win` と `result-lose` の両クラスが付く。
- ルールにある「同時に0になったら引き分け」が未実装。
→ `GAME_STATE.isGameOver` を追加し、フェイズ進行・召喚・攻撃・効果解決の入口で全部止める。引き分け判定も追加。

### A-3. `on_other_sent_to_trash` が無条件に発動する（`main.js:1099-1108`）
```js
for (const source of allFieldCards) {
    if (source && source !== card) await EffectLogic.resolveEffects(source, ..., "on_other_sent_to_trash");
}
```
- `action.filter`（アクア・サルベージ s006 の `attribute:"水"`）が**まったく参照されていない**。
- 「誰のカードが墓地に行ったか」も見ていないので、**相手のモンスターが破壊されてもドローする**。
- 逆に、召喚コストによるトラッシュ送り（`executeSummon`）ではこのトリガーが発火しない。
  水デッキの主要な墓地送り手段はコストなので、**本来一番発動してほしい場面で発動しない**。

### A-4. 永続魔術の「1ターンに1度」が「1ゲームに1度」になっている（`effect_logic.js:601-627`）
`cleanAllBuffs()` は `field.monsters` しかループしておらず、`field.magics` の `_usedLimits` を**リセットしていない**。
永続魔術（s006 アクア・サルベージ）の once_per_turn は初回発動後、二度と復活しない。
→ 魔術ゾーンも同じループに含める。

### A-5. 効果の対象選択がフィルタを無視する（`effect_logic.js:180-190` / `main.js:1738-1789`）
`_acquireTargets()` の manual 分岐はプレイヤー選択を `selectTargetUI()` に丸投げしているが、
`selectTargetUI` は **フィルタを見ずに「そのサイドの全モンスター」をハイライトする**。
```js
const slot = await selectTargetUI(targetSide, "monster", filter); // filter は使われていない
const cIdx = candidates.findIndex(c => c.slotIdx === slot);
if (cIdx !== -1) results.push(...);                                // 一致しなければ黙って何も起きない
```
- フレイムラッシュ（火属性のみ対象）で水属性を選ぶと、**魔術は消費されるのに何も起きない**。
- 何を選ばされているのかの案内テキストも無い。
→ 対象条件でハイライトを絞り、ヘッダーに「対象を選択してください」を出す。無効タップは無視する。

### A-6. 「冥界からの迎え」(s014) の一方的除去（`effect_logic.js:138-145`）
自分側の破壊と相手側の破壊が**独立した2アクション**。自分の対象選択で背景をタップしてキャンセルすると、
自分は無傷で相手だけ破壊できる。
→ 「自分の破壊」はコストとして先に確定させ、失敗したら効果全体を不発にする（＝1つの処理にまとめる）。

### A-7. 相手のLP回復で自分のカードが誘発する（`effect_logic.js:79-84`）
`applyHeal()` は**両者のフィールド全モンスター**に `on_lp_gain` を投げている。
相手が回復すると、こちらの聖界王レオニダスも +700 される。
→ 回復したプレイヤー側のカードのみに限定する。

### A-8（訂正: バグではなく仕様と判断）森界の門 + 森界の怒り
s007「森界の怒り」の条件は `is_weakened`＝`getCurrentPower(m) < m.power`。
s009「森界の門」は場に森界がいる限り**相手全体に常時 -200**。
s009 が1枚あるだけで相手モンスター全部が常に `is_weakened` 判定になり、s007 が実質無条件除去になる。

いったん「一時デバフのみを弱体化とみなす」方向に実装したが、これは誤り。
カードテキストの「元々の」は印刷値と**現在の実数値（常時オーラ込み）**の比較を指しており、
一時デバフに限定する理由はない。**s009 との組み合わせは【森界】の意図した除去手段として、
現在の実数値ベースの判定に戻した。** s024「森界の壁」の `attackerWeakenedBy` も同じ基準。

## 1-C. CPU（重大度B〜C）

- `executeBattlePhase` の `totalPotential` 計算で `reduce` の `idx` が**フィルタ後配列の添字**になっている（`cpu_logic.js:206`）。今は実害が出ていないが誤り。

# 2. UI / 操作性

## 2-1. スマホでスクロールが効かない（重大）
`style.css:29-37` の `body { touch-action: none; }` により、**子要素のタッチスクロールが全滅**している。
`#info-text` だけ `touch-action: pan-y` で救済されているが、以下は指で動かせない:

- デッキビルダーのライブラリ（`.library-grid`／全58枚・6列＝10行）と構築中デッキ（`.deck-grid-scroll`）
- トラッシュ閲覧モーダルの横スクロール（`#trash-card-list`）
- 手札選択モーダルの横スクロール（`.horizontal-list`）
- デッキ選択画面（`#deck-list-container` はスクロール領域ですらない）

→ 各スクロールコンテナに `touch-action: pan-y`（横なら `pan-x`）を明示する。

## 2-2. タップ位置がずれる（重大）
```css
.zone::after { top:-15px; left:-15px; right:-15px; bottom:-15px; z-index:5; }
```
ゾーン間の隙間は 8px なので、隣接ゾーンの当たり判定が**左右で22px重なる**。
重なった領域では DOM 順で後ろのゾーンが勝つため、**枠の境目を押すと隣のスロットが選ばれる**。
さらに `detectHitSlot()` の幾何フォールバックは ±20px の矩形を index 0 から順に走査して**最初に当たったものを返す**ので、
判定が常にスロット0寄りに偏る。

→ 拡張マージンを 6〜8px に縮める＋幾何判定は「中心からの距離が最小のゾーン」を選ぶ方式に変える。

## 2-3. 小さい画面でUIが重なる
- `#card-info-panel` は `left:10px; width:280px`（右端290px）、`#surrender-btn` は `right:15px`。
  **幅360pxのスマホでは確実に重なる。**
- `#field-perspective-wrapper` の `padding-top:210px / padding-bottom:140px` は固定値。
  画面高 640px 級だとフィールドの表示領域が 290px しか残らず、カードが潰れる／見切れる。
- `.hud-stats.opt {top:32%}` `.ply {top:62%}` `#next-phase-btn {top:55%}` は**%固定**なので、
  端末のアスペクト比が変わると盤面と重なる。横向き（ランドスケープ）は完全に未対応。

## 2-4. PC が「細い縦長」のまま
`@media (min-width: 481px)` は `#game-viewport` を **480px幅に固定**するだけ。
1280×800 の PC でも、カードは `--card-max-width: 65px` の豆粒サイズで、画面の左右に巨大な余白ができる。
「PCでも快適に」を満たすなら、次のどちらか:

- **(推奨) スケール方式**: 設計サイズ（例 480×900）を維持したまま `#game-viewport` に
  `transform: scale(min(vw/480, vh/900))` を掛ける。レイアウト崩れゼロで一気に大きくできる。
- **可変方式**: `--card-max-width` / `--card-max-height` / パネル幅 / padding をブレークポイントごとに拡大。手間は増えるが精細。

デッキビルダーも PC 未対応で、`grid-template-columns: repeat(6, 1fr)` のまま 1920px に広げると
カード1枚が 300px 超になる。`repeat(auto-fill, minmax(70px, 1fr))` にすべき。

## 2-5. その他
- `index.html` のハードコード初期値（`HAND: 5` / デッキ `20`）が実際（手札6・デッキ30）と違う。初回描画で一瞬見える。
- 情報パネルは常時表示で、未選択でも 280×150px の面積を占有している。
- コスト選択は必要数に達した瞬間に自動で次へ進むため、**選び直しができない**。「確定」ボタン方式が安全。
- 対象選択・コスト選択の最中に「今なにを求められているか」の文言が一切出ない。
- 効果解決中もフェイズボタン以外の操作がロックされない（`isAnimating` を見ているのはフェイズボタンだけ）。
- デッキビルダーのレベルフィルタは Lv1〜4 のみ（ルール上は Lv5 まで）。

# 3. デッキバランス診断

## 3-1. 現状の構造的な問題

**(a) 上級モンスターがコストに見合っていない**

| Lv | コスト（体数） | パワー帯 | 1体あたり効率 |
|---|---|---|---|
| 1 | 0 | 200〜500 | — |
| 2 | 1 | 600〜1000 | 1000/1体 |
| 3 | 2 | 1200〜1500 | 750/1体 |
| 4 | 3 | 1700〜2100 | 700/1体 |

戦闘は「1体1回、対象を選んで殴る」ため、**横に並べたほうが総打点も攻撃回数も多い**。
Lv1×3（計1300・3回攻撃）と Lv4（2100・1回攻撃）なら、盤面が空いていれば前者が有利。
つまり現状、上級を出す理由は**パワーではなく効果**しかない。効果が弱い上級（m026 アサルト・フレーム Lv3 1500 バニラ）は完全な死に札。

**(b) 全デッキが「3枚×10種」で固定**
上級モンスターまで一律3枚積みなので事故要因になり、
かつ全デッキに同じ汎用札（m027 リサーチ・ポッド）が3枚入っていて**構築の個性を削っている**。

**(c) 勝ち筋の格差**
除去を持つデッキ（草・闇）と持たないデッキ（光・水）で、盤面の解決力が違いすぎる。

## 3-2. デッキ別評価（5点満点）

| | 展開力 | 打点 | 除去 | 耐久 | 安定性 | 総合 |
|---|---|---|---|---|---|---|
| 火（炎界） | 5 | 4 | 1 | 2 | 4 | **強** |
| 水（海界） | 3 | 3 | 2 | 3 | 3 | 中 |
| 草（森界） | 2 | 2 | 5 | 2 | 4 | 中〜強 |
| 光（聖界） | 2 | 3 | 0 | 5 | 3 | **弱** |
| 闇（冥界） | 4 | 4 | 3 | 3 | 4 | **最強** |

**闇（冥界）— 最強**
m023 冥界王が**毎ターン無償で闇モンスターを蘇生**するのが強すぎる。蘇生した個体はそのまま次の上級のコストになるため、
「毎ターン上級を出しながら盤面を維持する」という他デッキに真似できないループが成立する。
m031 ソルゴス（墓地肥やし→即蘇生）で単体からでも展開でき、s014 で除去まで持つ。弱点らしい弱点がない。

**火（炎界）— 強い（基準にすべき完成度）**
s001／m004 の展開 → m005 炎界王で火属性全体 +300、という筋が一本通っている。
除去を持たないのが唯一の弱点で、「並べて殴る」というコンセプトが明快。**バランス調整の基準デッキはこれが適任。**

**草（森界）— 除去に依存**
s009 + s007 の（上記 A-8 の）バグ的コンボを直すと、除去力が一気に落ちて中位以下になる。
展開手段が s008（手札に加えるだけ）しかなく、上級のコストを揃えられないのが根本問題。m012（Lv1 パワー200）が細すぎる。

**水（海界）— コンセプトは良いが遅い**
「トラッシュに送られた時」がテーマで、**召喚コストで自分の墓地効果を誘発させる**という設計は秀逸。
ただし現状、自分から墓地に送る手段がコストと m027 しかない。
m010 海界王（2100）は**倒されて初めて効果が出る**ので、盤面に出た瞬間は仕事をしない＝テンポが悪い。
m026 アサルト・フレーム（無属性 Lv3 バニラ）はテーマと噛み合っておらず、海界の Lv3 が欲しい。
※ 現在は s006 の実装バグ（A-3/A-4）で不当に強く見えている。修正すると最下位争いになる。

**光（聖界）— 明確に弱い**
最大打点が m019 の 2700（回復条件付き）で、**相手のLP5000を削り切る手段がない**。
除去0・展開2なので、盤面を取られると何もできない。デッキ切れもリフレッシュ規定で負けにならないため、
「負けにくいが勝てない」＝**試合が終わらないデッキ**になっている。
回復を「勝ち筋」に変換するカードが最低1枚は必要（例: 回復した数値ぶん相手にダメージ／回復量に応じて打点上昇）。

# 4. ルール改正の提案

## 4-1. 現行ルールの問題（ご指摘の通り）

> 「絶対に場にモンスターを残さなければ、上級モンスターを出せない」

これは **「勝っている側がさらに有利になる」構造**（rich get richer）になっています。
盤面を全部取られた側は上級を出せず、Lv1 を1体ずつ出しては殴られるだけで、逆転の余地がない。
カードゲームとして一番つらい負け方です。

また「レベル」が **強さの指標** と **召喚コスト** の二重の意味を持っているのも、しっくりこない原因だと思います。
Lv2 が「1体リリース」、Lv3 が「2体」…という対応が暗黙のルールになっていて、カードを見ても直感的に分かりません。

## 4-2. 推奨案：「リンク値（LINK）」への一本化 ＋ 手札リリース

**① レベルを「リンク値」に読み替える**
カードには LINK 1〜5 を表記し、**素材のリンク値の合計**でコストを支払う。
「Lv1以上を3体」ではなく「合計 LINK 3 以上」。

- LINK 3 のモンスター → `LINK1 + LINK1 + LINK1` でも `LINK2 + LINK1` でも出せる
- **1つのコストに複数の組み方が生まれる**＝構築とプレイングの幅が出る
- カードに書いてある数字がそのままコストなので、直感的（遊戯王のリンク召喚に近い読み味）

**② 素材は「フィールド」だけでなく「手札」からも出せる（本命）**
手札のモンスターをトラッシュに送って素材にできる。ただし **手札から使えるのは1回の召喚につき1体まで**。

- 盤面が空でも、手札2枚（場のLINK1 + 手札のLINK1 など）から巻き返せる
- 「盤面のアドを使うか、手札のアドを使うか」という**毎ターンの選択**が生まれる
- 水・闇の「トラッシュに送られた時」テーマとも噛み合う
  （※ 手札からの素材で墓地効果を誘発させるかは要判断。誘発させると水が一気に強くなるので、
  「**フィールドから**トラッシュに送られた時」と誘発条件を明文化するのが無難）

**③ 上級のパワーを引き上げる**
①②でコストが軽くなるぶん、Lv3=1600〜1800 / Lv4=2400〜2600 に上げて「上級を出す意味」を作る。

この3点だけで、
「コンボは決まりやすい（複数ルートで上級に届く）／プレイングは考える（手札と盤面のどちらを切るか）／構築の幅が出る（リンク値の組み合わせ）」
というご希望に一番近づくと考えます。

## 4-3. 検討したが採らなかった案

| 案 | 却下理由 |
|---|---|
| マナ／エナジー制（ターン毎に自動で+1、レベル以下なら召喚可） | 事故は減るが、上級が確定で出るので**引いたカードで勝負が決まるドローゲー**になり、プレイングの妙が消える |
| トラッシュのモンスターも素材にできる | 闇（冥界）だけが一方的に得をして、格差が広がる |
| LPを払って召喚できる救済ルール | 負けている側ほど払えないので、逆転要素として機能しない |
| 毎ターン自動でトークンを生成 | モンスターゾーンが3枠しかないため盤面を圧迫し、かえって窮屈になる |

## 4-4. あわせて入れたい細かいルール

- **永続魔術は自分の意思でトラッシュに送れる**（魔術ゾーン3枠が埋まって詰む問題の解消）
- **引き分け条件の実装**（同時に0／勝利条件の同時達成）
- **ターン数上限**（例: 通算30ターンで LP の多い側の勝ち）。リフレッシュ規定があるためデッキ切れで終わらず、
  光デッキ同士だと永久に終わらない可能性がある
- **起動効果をバトルフェイズでも使える**ようにする（ルール本文と実装を一致させる）
